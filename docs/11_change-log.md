## Scope Change Summary

| Feature | Baseline | Current | Risk | Demo Impact |
|---|---|---|---|---|
| TYK2 story | Positive lead-loop target | Negative self-falsification case | Positive target remains TBD | Stronger autonomy/scientific demo |
| Molecule optimization | TYK2/deucravacitinib direct optimization | Gate-controlled branch after target `ADVANCE`; `METHOD_ONLY` allowed | End-to-end positive branch incomplete | Honest blocked state |
| ADMET | TDC as immediate predictor | Planned ADMET-AI, runtime validation required | Dependency unverified | Disclosed |
| Synthesis | AiZynth throughout loop | SA/RAscore bulk, AiZynth top 5 | RAscore runtime unverified | Faster/replayable |
| Transparency | Generic logs/“thinking” | Decision trace + evidence/rules/actions/failures | UI not built | Better final-demo contract |
| LLM role | Undecided runtime, unclear authority | Local Ollama selects the next action from a 7-item allow-list and writes the explanation; ON by default on the serving plane, any installed model selectable per request | Model text is rejected, not corrected, on violation; a refused selection falls to a fixed policy | Reviewer sees model vs template provenance per claim, and model vs policy provenance per step |
| Agent autonomy | A roster of 11 named agents that executed nothing | One loop where the model chooses the action and deterministic code executes it and writes every observation | The model can drive a run into a dead end; the step budget and the repeat check bound it | The agent proposes molecule optimization on a rejected target and the harness refuses it on the screen |
| Chemistry | Authored descriptors, 16-bit hand-written fingerprint, alert strings | Optional RDKit backend computes every property from SMILES; reference stays default | RDKit is optional, so two lineages must stay in step | Each rejection cites a real substructure, not a label |
| Console data | Hand-authored TypeScript fixtures; the core could be deleted with no visible change | Runs projected from the decision core over a read-only API; fixtures kept as a labelled offline fallback | Two run sources coexist, so the classification badge has to carry the distinction | Stopping the server removes the computed runs — the screen is evidence, not a picture |
| Scenario coverage | Two packets seeded at start-up; a reviewer could watch a rejection but never cause one | Four rule-isolating presets plus a free-text packet a reviewer writes themselves, run in a sandbox that stores nothing | Submitted evidence is unapproved by definition, so the badge and the closed gate have to carry that | The rejection becomes reproducible on the reviewer's own input instead of on our fixture |

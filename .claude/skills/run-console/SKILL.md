# H2L-Forge 콘솔 실행

한 줄입니다. 저장소 루트에서:

```bash
./scripts/dev.sh
```

하네스(:8765)와 웹 개발 서버(:4173)를 함께 띄우고, 둘 다 응답하고 `/api` 프록시가
붙은 것까지 확인한 뒤 주소를 출력합니다. Ctrl-C면 둘 다 내려갑니다.

## 두 프로세스가 모두 필요합니다

- **하네스** `:8765` — 파이썬 결정 코어. 규칙을 실행하고 판정을 계산합니다.
- **웹** `:4173` — vite 개발 서버. `/api/*`를 하네스로 프록시합니다.

하네스가 없어도 콘솔은 **열립니다.** 대신 고정 픽스처 2건만 보이고 "실제 하네스
API"는 비활성입니다. 그러니 "화면이 떴다"를 "규칙이 돈다"로 읽으면 안 됩니다.
모달 하단 "연결 방식"에서 **실제 하네스 API가 선택 가능한지**가 실제 판정 기준입니다.

## 포트가 막혀 있다고 하면

스크립트가 PID를 알려주고 멈춥니다. 이건 고장이 아니라 의도입니다. 예전 세션의
개발 서버가 남아 있으면 vite가 4174, 4175로 밀리고, 그렇게 밀린 서버는 QA 게이트
기본 주소(:4173)와 어긋나며 옛날 코드를 계속 보여 줍니다.

```bash
ps -p <PID> -o command=   # 무엇인지 확인하고
kill <PID>                # 정리
```

포트를 바꿔야 하면 `H2L_WEB_PORT` / `H2L_HARNESS_PORT`로 넘깁니다.

## 확인 방법

브라우저에서 `http://127.0.0.1:4173/`을 열고 **새 실행**을 누릅니다. 하네스가
붙어 있으면 시나리오 4종(양성 근거 · 실패 임상 · 적응증 불일치 · 맥락 근거만)이
뜹니다. 2종(IBD 근거 검토 · 분자 비교 UI 점검)만 보이면 픽스처 폴백 상태입니다.

## QA 게이트를 돌릴 때

두 게이트는 서로 다른 하네스 상태를 전제합니다. 이 스크립트를 켜 둔 채로는
둘 다 못 돕니다.

```bash
cd web_dongseop
npm run qa         # :8765 가 꺼져 있어야 함 (오프라인 폴백 검증)
npm run qa:online  # :8765 가 비어 있어야 함 (게이트가 직접 켰다 끔)
```
